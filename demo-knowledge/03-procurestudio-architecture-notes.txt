DEVELOPERTWIN DEMO KNOWLEDGE — PROJECT ARCHITECTURE NOTES
Document ID: DEMO-ARCH-008 | Product: ProcureStudio | Environment: Sandbox
Everything below is fictional and intended for your training demonstration.

SYSTEM OVERVIEW
ProcureStudio is a training ERP for managing purchase requests, approval routing, and procurement records.

TECHNOLOGY STACK
Frontend: React 19 + TypeScript + Vite.
Backend: ASP.NET Core .NET 9 Minimal APIs.
Database: PostgreSQL 16 for purchase requests, line items, approver assignments, and audit logs.
Messaging: RabbitMQ for events after a request is approved.
Vector retrieval: NOT part of the ERP. DeveloperTwin independently uses Ollama embeddings and Qdrant for analysis of these notes.

LOGICAL MODULES
- Requests API: handles draft, submit and request queries.
- Approval Service: calculates responsible approver from authoritative policy configuration.
- Procurement Service: transforms an approved request to a purchase order.
- Notification Worker: consumes events and sends mock status notifications.
- Audit Service: appends security and workflow audit records.

EVENT FLOW
1. React sends POST /api/purchase-requests to Requests API.
2. Requests API validates fields, saves request + items in PostgreSQL transaction, returns ID.
3. Employee submits request; backend evaluates approval policy, sets PendingApproval, assigns approver.
4. Approver records an approval decision; one DB transaction updates state and writes an outbox event.
5. Background worker delivers outbox events to RabbitMQ, then Notification Worker processes them.

ENGINEERING DESIGN DECISIONS
- Database per service not assumed for this small demo; use a shared transactional database with schema separation.
- Outbox pattern avoids 'database success, message broker publish failed' inconsistency.
- Use optimistic concurrency token on purchase request status updates.
- Use OpenTelemetry traces for inbound API request -> database write -> publish -> consumer.
- Do not place business authorization checks in a chatbot prompt. They belong in deterministic API logic.

LOCAL DEVELOPMENT
1. Start PostgreSQL and RabbitMQ containers.
2. Configure user secrets or environment variables; never commit connection passwords.
3. Run dotnet restore; dotnet run for API.
4. Run npm ci; npm run dev for React.
5. Launch automated API tests with test data.

KNOWN LIMITATIONS
No external supplier API, no production identity provider, demo-only email notifications.
